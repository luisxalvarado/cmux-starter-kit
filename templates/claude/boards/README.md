# Workspace boards

One board per cmux workspace. The board is the single source for what that workspace's card shows in the
sidebar; `~/.claude/loop/board_sync.py` copies it into cmux every 2 minutes and on every `/log` and
`/pre-compact`. Never edit the sidebar by hand: edit the board.

File name: `<workspace-slug>.md`. Format (keep it this small):

```
Workspace: Main                   <- the exact cmux workspace title
Phase: 1 of 3 · Getting started   <- optional; drives the bar (1 of 3 = 33%)
Now: Try /prime in a new tab      <- the one line description on the card

## Phases                         <- optional: every phase, so the page shows the whole picture
- [x] Phase 0: what it covered
- [~] Phase 1: the current one
- [ ] Phase 2: what comes next

## Checklist                      <- the steps of the current work, in order
- [x] done item
- [~] in progress item
- [ ] not started item

## Waiting on you                 <- shows as "N decisions" on the card
1. One open decision per line, most urgent first → where to answer it (a tab name)
```

Rules for threads updating a board:
- **Now** is the next thing that happens or what is blocking, in 60 characters or fewer. Rewrite it whenever it changes.
- Tick a checklist item only with proof. "Built, not tested" stays `[~]`.
- Add a checklist item only when the owner agreed to that work. Anything else gets "add it, park it, or skip?" first.
- Waiting on you holds only decisions the owner owes, each ending with "→ where to answer". A deadline written as
  "due 3 Oct" or "before 12 Nov" makes the card show 📅 when it is 2 days away.
- Tapping "Overview" on a card opens `~/.claude/boards/.views/<slug>.md`, generated by board_sync.py (never edit it).
- Fixed dates for a workspace (a trip, a launch) go in `milestones.json` next to this file:
  `{"Main": [{"label": "Trip", "date": "2026-11-02"}]}`. The card shows "Trip in 12d" when nothing else is happening.
- Several threads can share a workspace; each updates only its own lines and keeps the rest.
